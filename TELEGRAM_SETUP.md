# Подключение AUTO_RAZBOR к Telegram

## Что уже реализовано
- Mini App: поиск марок, список моделей и поколений.
- API каталога: `GET /api/catalog`.
- Проверка подписи Telegram WebApp `initData`: `POST /api/telegram/auth`.
- Базовый webhook для команд `/start` и `/help` (его нельзя включать, пока не перенесена логика действующего бота).
- Отдельные флаги для настройки кнопки Mini App и webhook.

## Важное правило: не ломать работающего бота
У Telegram может быть только один активный webhook на бота. Поэтому сервер **не меняет webhook и кнопку меню автоматически** при каждом запуске.

- `ENABLE_TELEGRAM_MENU_BUTTON=true` — явно разрешает серверу установить кнопку Mini App.
- `ENABLE_TELEGRAM_WEBHOOK=true` — явно разрешает серверу заменить webhook на этот сервер.
- Оба значения по умолчанию `false`. Не включайте webhook, пока не перенесены и не проверены все функции старого бота.
- Если бот уже работает на конструкторе/другом сервере, сначала согласуйте способ добавления Mini App с этим сервисом. Не вводите токен в сторонние чаты.

## Развёртывание
Нужен публичный HTTPS-хостинг с Node.js 20+ (например, Render, Railway или VPS).
1. Подключить репозиторий `Kapusta1a/Auto_razbor` к хостингу.
2. Команда запуска: `npm start`.
3. Проверить `https://ВАШ-ДОМЕН/health` — ожидается JSON с `ok: true`.
4. URL самого приложения — корневой HTTPS URL сервиса.

Токен `BOT_TOKEN` хранить только в секретах хостинга. Никогда не отправлять его в чат, GitHub или клиентский JavaScript.

## PRO и платежи
PRO-подписка ещё не реализована. Перед запуском нужны Telegram Stars (валюта `XTR`), обработка `pre_checkout_query` и `successful_payment`, база данных подписок, защита от повторной обработки платежей и экран статуса подписки. Нельзя выдавать PRO только по факту нажатия кнопки или доверять данным клиента.

## Ограничения текущего каталога
`data/catalog.seed.json` — демонстрационный стартовый набор, а не полный мировой справочник. Годы, коды поколений и региональные отличия требуют проверки. Технические характеристики и типовые неисправности нельзя публиковать как подтверждённые без источников.
